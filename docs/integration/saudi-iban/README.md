# التحقق من الآيبان السعودي — حزمة التكامل للمبرمجين

حزمة مرجعية للتحقق من صحة الآيبان السعودي وفق المعيار ISO 13616 وخوارزمية ISO 7064 MOD 97-10، مع جدول رموز البنوك التي تصدرها ساما.
القواعد ورموز الأخطاء واحدة في كل التنفيذات، وتُختبر كلها على ملف حالات الاختبار نفسه.

| الملف | الغرض |
|---|---|
| `saudi_banks.json` | جدول البنوك: رمز الآيبان، الاسم بالعربية والإنجليزية، الحالة، رمز SWIFT ودرجة توثيقه. **مصدر البيانات الوحيد** للتنفيذات |
| `python/saudi_iban.py` | التنفيذ المرجعي بلغة Python (بلا مكتبات خارجية) |
| `typescript/saudiIban.ts` | التنفيذ نفسه بلغة TypeScript، للواجهات وخوادم Node |
| `test_vectors.csv` | 48 حالة اختبار مشتركة (صحيحة وخاطئة) مع النتيجة المتوقعة ورمز الخطأ |
| `python/test_saudi_iban.py`، `typescript/saudiIban.test.ts` | تشغيل حالات الاختبار على كل تنفيذ |
| `saudi_iban_bank_codes.xlsx` | المرجع لغير المبرمجين: جدول البنوك، مدقق آيبان بمعادلات Excel، شرح الخوارزمية خطوة بخطوة |

## 1. هيكل الآيبان السعودي

24 خانة، وصيغته في سجل SWIFT للآيبان: `SA2!n2!n18!c`

| المواقع | الجزء | الطول | مثال |
|---|---|---|---|
| 1–2 | رمز الدولة | 2 حرف | `SA` |
| 3–4 | خانتا التدقيق | 2 رقم | `03` |
| 5–6 | رمز البنك (تصدره ساما) | 2 رقم | `80` |
| 7–24 | رقم الحساب | 18 خانة (أرقام عملياً) | `000000608010167519` |

خانتا التدقيق تُحسبان من الحساب كاملاً، فلا يوجد حقل تدقيق ثابت لكل بنك.

## 2. خطوات التحقق — بهذا الترتيب

أول قاعدة تفشل هي رمز الخطأ المُعاد.

| # | القاعدة | رمز الخطأ | الرسالة |
|---|---|---|---|
| 0 | التنظيف: حذف المسافات والشرطات والمسافة غير المنقسمة وعلامتي الاتجاه (U+200E/U+200F)، تحويل الأرقام العربية الهندية `٠–٩` و`۰–۹` إلى `0–9`، تحويل الحروف إلى كبيرة، وحذف بادئة `IBAN` إن وُجدت | — | — |
| 1 | النص غير فارغ | `EMPTY` | لم يُدخل آيبان |
| 2 | الأحرف من `A–Z` و`0–9` فقط | `INVALID_CHARACTERS` | يحتوي رموزاً غير مسموحة |
| 3 | يبدأ بـ `SA` | `COUNTRY_NOT_SA` | رمز الدولة ليس SA |
| 4 | الطول 24 بالضبط | `WRONG_LENGTH` | طول الآيبان السعودي 24 خانة |
| 5 | يطابق `^SA[0-9]{2}[0-9]{2}[0-9A-Z]{18}$` | `INVALID_FORMAT` | خانتا التدقيق ورمز البنك يجب أن تكون أرقاماً |
| 6 | خانتا التدقيق ليستا `00` أو `01` أو `99` (المسموح 02–98) | `INVALID_CHECK_DIGITS` | خانتا التدقيق غير مسموحة |
| 7 | باقي MOD-97 يساوي 1 | `CHECKSUM_FAILED` | خطأ في كتابة الآيبان |
| 8 | رمز البنك موجود في `saudi_banks.json` | `UNKNOWN_BANK` | رمز البنك غير مسجل |

**تحذيرات لا تُسقط الآيبان:**
- `LEGACY_BANK`: رمز بنك مدمج، 40 لسامبا و50 للبنك الأول. الآيبان صحيح حسابياً، لكن الحساب قد يكون نُقل إلى البنك الدامج.
- `UNKNOWN_BANK`: يظهر تحذيراً بدل خطأ فقط مع `strict_bank=False` أو `strictBank: false`. فائدته ألا يُرفض بنك رخّصته ساما بعد آخر تحديث للجدول.

القاعدة 6 ضرورية: الحساب الذي خانتا تدقيقه الحقيقيتان 97 أو 98 يجتاز اختبار MOD-97 أيضاً بـ `00` أو `01`. حالات الاختبار تغطي ذلك.

## 3. خوارزمية MOD-97

```
rearranged = iban[4:] + iban[0:4]           # انقل أول 4 خانات إلى النهاية
remainder  = 0
for ch in rearranged:
    v = digit value of ch (0–9) أو A=10 … Z=35
    remainder = (remainder * (v > 9 ? 100 : 10) + v) mod 97
valid ⇔ remainder == 1
```

الحساب حرفاً بحرف يغني عن الأعداد الكبيرة، فيصلح لأي لغة، ومنها SQL وCOBOL.

**توليد خانتي التدقيق** لرمز بنك ورقم حساب من 18 خانة:
`check = 98 − mod97("SA00" + bank_code + account)`، وتُكتب برقمين مع صفر بادئ.

## 4. الاستخدام

**Python**
```python
from saudi_iban import validate, ERRORS
r = validate(user_input)            # validate(user_input, strict_bank=False) لقبول بنك غير مسجل مع تحذير
if r.valid:
    save(r.iban)                    # الصيغة الإلكترونية: 24 خانة بلا مسافات
    show(r.formatted, r.bank["name_ar"], r.bank["swift"], r.warnings)
else:
    show_error(ERRORS[r.error])
```

**TypeScript** (ESM؛ يحتاج `resolveJsonModule`)
```ts
import { validateSaudiIban, ERROR_MESSAGES_AR } from "./saudiIban";
const r = validateSaudiIban(input);
if (!r.valid) showError(ERROR_MESSAGES_AR[r.error!]);
```

## 5. توصيات التكامل

1. **تحقّق في الواجهة وفي الخادم معاً.** الواجهة لراحة المستخدم، والخادم هو الحكم.
2. **خزّن الصيغة الإلكترونية** (`iban`: 24 خانة بلا مسافات)، واعرض الصيغة المطبوعة (`formatted`) فقط.
3. **صحة الآيبان حسابياً لا تعني أن الحساب موجود** أو أنه باسم المستفيد. قبل أول تحويل لمستفيد جديد، تحقّق من الاسم عبر البنك، باستعلام اسم المستفيد في خدمات الدفع المحلية.
4. **الآيبان بيانات شخصية.** أخفه في السجلات والرسائل (مثلاً `SA03 •••• •••• •••• •••• 7519`) ولا تكتبه كاملاً في ملفات السجل.
5. **رمز SWIFT للعرض والتحويل الدولي فقط.** لا تعتمد على رمز درجة توثيقه `single_source` أو `unconfirmed` دون تأكيده مع البنك.
6. **عند إضافة بنك حدّثوا `saudi_banks.json`.** التنفيذان يقرآن منه، ولا يوجد جدول بنوك منسوخ داخل الشيفرة. أما ملف Excel فيُولَّد مع ملف JSON من السكربت `scripts/gen_saudi_iban_workbook.py` في المستودع، فيُضاف البنك هناك ليظهر في الاثنين معاً.

## 7. بيانات البنوك ومصادرها

- **رموز البنوك:** من المعرّفات التي تصدرها ساما، كما ينشرها [EngMEita/saudi-banks](https://github.com/EngMEita/saudi-banks)، مع مراجعة cubbbix.com وvalidatefin.com.
- **رموز تأكدت بآيبانات فعلية تجتاز MOD-97:** 36 لبنك D360، و73 لبنك أبوظبي الأول، و78 لبنك STC.
- **رموز SWIFT:** من أدلة SWIFT العامة (Wise، XE، theswiftcodes، ksaexpats، alaan). الحقل `swift_confidence` يبيّن درجة التوثيق:

  | القيمة | المعنى |
  |---|---|
  | `confirmed` | ورد في أكثر من مصدر |
  | `single_source` | ورد في مصدر واحد |
  | `unconfirmed` | لم يُعثر على مصدر |

- **حدود الجدول:** ساما لا تنشر سجلاً عاماً مفتوحاً لهذه الرموز، فطابقوا الجدول مع ساما أو البنك قبل الإنتاج. Vision Bank غير مُدرج لأن رمزه لم يُتحقق منه.
