# ADR 0005: Gap-free document numbering, and the ISO and permission seeds

Status: accepted by the owner (2026-10-12, docs/31-owner-decisions.md) for the decisions it implements: DQ-B02-4 and Q-PLT-08 (request and proforma numbers are gap-free; O-12 of tools/dbgen/erd_open_items.py), DQ-B05-5 (complete country and currency lists, with IsActive and the ISO version recorded), DQ-F07-1 and DQ-F09-1 (the permission codes). It follows ADR 0004: tenant data changes through procedures that the row filters keep to the bound tenant, and the application role loses the direct rights those procedures replace.

## Context

- FR-PLT-026 and BR-PLT-010 require numbers that two concurrent requests never share and that a rollback never loses; AC-PLT-3 tests this under concurrency. The model had the tables (`cfg.NumberSequenceDefinition`, `cfg.NumberSequence`, `cfg.NumberIssue`) but no allocation, and `tp_app` could write the counters.
- A gap-free number conflicts with rollbacks and concurrent writers (O-12). The owner decided that requests and proformas are gap-free and other series may have gaps.
- The platform seed of ADR 0004 lacked the ISO country and currency lists and the permission catalogue (O-25).

## Decision

### 1. Allocation inside the business transaction (`db/static/039_numbering.sql`)

- One counter row per (tenant, definition, company when the scope is COMPANY, period). `cfg.usp_AllocateNumber` reads it with `UPDLOCK, HOLDLOCK`, raises it, and writes the issued number to `cfg.NumberIssue`, all in the caller's transaction. Hence:
  - a rollback of the business transaction returns the number with the business row, so no number is lost;
  - a second request for the same counter waits until the first transaction ends, so no number is taken twice;
  - a missing counter row is created under the key-range lock, so two first allocations of a period cannot both create it.
- A GAP_FREE sequence is refused outside a transaction (50029): a number committed alone would leave a gap when the business insert then fails. A sequence that allows gaps may be called without one.
- Formatting: `{seq}` or `{seq:000}` (the zeros set the minimum width; a longer number widens and is never cut), `{erp}` (the company's normalised ERP code, COMPANY scope only), `{yyyy}` and `{yy}` (the year of the period). The result is at most 60 characters (50031).
- Periods: CALENDAR_YEAR uses the year of `@OnDate`; FISCAL_YEAR (COMPANY scope) uses the year in which the company's fiscal year containing `@OnDate` ends (BR-ORG-004); NONE keeps one counter. The application passes `@OnDate` in the tenant's time zone; without it the UTC date is used.
- `cfg.usp_VoidNumber` marks a number VOID with a reason (50032). A void number is never issued again (BR-PLT-010); cancelling a numbered request voids its number (BR-WFL-013).
- A trigger checks each definition when it is written (50031):
  - exactly one `{seq}` tag and only the known tags, and `{erp}` only at COMPANY scope;
  - the request definitions (`req:<TypeCode>`, BR-WFL-013) and `PROFORMA` must be GAP_FREE, as the owner decided.
- BR-WFL-013 writes request patterns as `{prefix}-{yy}-{seq:0000}`. Each request type has its own definition, so the tenant pack writes the prefix as text (`LCP-{yy}-{seq:0000}`); there is no `{prefix}` tag.
- Both procedures run as the caller (no EXECUTE AS), so the row filters keep them to the bound tenant. `tp_app` may execute them, and loses INSERT and UPDATE on `cfg.NumberSequence`, INSERT on `cfg.NumberIssue`, and UPDATE on its number, status and void columns. It may still link an issued number to its entity (`EntityType`, `EntityId`).

### 2. ISO countries and currencies (`db/seed/101_iso_reference.sql`, DQ-B05-5)

- Generated by `tools/dbgen/gen_iso_seed.py` and committed, so CI does not need its sources. The header records the data version: Debian iso-codes 4.16.0-1 for the codes and English names, CLDR (Babel 2.17.0) for the Arabic names, and the ISO 4217 minor units for the decimals (CLDR differs for some currencies, such as IQD).
- All 249 ISO 3166-1 countries and 157 currencies, all active.
- ISO 4217 changes after that iso-codes version are applied:
  - added: ZWG (2024) and XCG (2025);
  - not seeded, because withdrawn: HRK, SLL, ZWL and ANG. A new platform holds no history in them, and ISO reuses numeric codes (XCG took 532 from ANG), which `ref.Currency` keeps unique. A currency withdrawn later is set inactive, not deleted.
- Not seeded either: metals, units of account, funds and test codes, and the four-decimal CLF and UYW, since `ref.Currency` allows 0 to 3 decimals.
- IsGcc, WeekendDays and DialCode are set for the six GCC states only (BR-CAT-018). Their weekends are proposals to verify (Q-CAT-12); the other dial codes need an ITU source.

### 3. Permission catalogue (`db/seed/102_permissions.sql`, DQ-F07-1, DQ-F09-1)

- Generated by `tools/dbgen/gen_permission_seed.py` from DOC-F07 section 3, DOC-F09 sections 3.1 and 3.2 and the role matrices of specs 10 to 14: 138 codes with their module and their Arabic and English names.
- The generator fails when a code in the documents has no English name, or a name has no code. CI step 2 regenerates the file and compares it with the committed one, so the catalogue and the documents cannot drift apart silently.
- Five permissions are locked to the treasury manager and the facilities officer (`LockedToRoleCodes ["TM","FO"]`, BR-PLT-019): `party.identity.reveal`, `party.identity.image.view`, `party.pack.export`, `party.export.sensitive` and `acc.signature.image.view`. They and `acc.reveal` are sensitive (BR-PLT-008).
- The default assignment of permissions to roles belongs to the CORE.ROLES tenant pack (DOC-B05 section 5.1), not to this seed.

Both seeds insert only: a row that exists is never changed, so an operator's later correction stays (FR-CAT-026). CI step 4b runs the platform seed twice and expects nothing to change.

### Error numbers added

| Code | Meaning |
|---|---|
| 50029 | Gap-free number requested outside a transaction |
| 50030 | No active definition with this key, or no company or ERP code for it |
| 50031 | Invalid pattern, a request or proforma sequence that allows gaps, or a number longer than 60 characters |
| 50032 | Number not issued, or no reason given to void it |

## Consequences

- **Tests.** Every case passes in CI (`tools/ci/db_ci.sh` steps 2, 4b, 12 and 13):
  - N1 to N8 in `db/tests/numbering_tests.sql`: definition checks, AC-PLT-3 (`003-XX01-26` after `001` and `002`, a void number not reused, `001-XX01-27` in the new year), reuse after a rollback, widening from 99 to 100, fiscal years, company checks, direct rights, tenant isolation;
  - `tools/ci/numbering_concurrency.sh`: six connections take numbers of one gap-free sequence at the same moment, each in its own transactions, and a quarter of the transactions roll back. The committed numbers run 1 to 114 with no duplicate and no gap, and they alternate between the connections, which shows the connections really ran together.
- **Application.**
  - Take the number last, just before the commit, in the transaction that writes the numbered row. Pass the tenant's date as `@OnDate`.
  - A request has a draft number `D-xxxxxx` outside the sequence until it reaches its numbering stage (BR-WFL-013); a number is taken once and is not taken again when the stage is entered again.
  - The tenant packs (FR-PLT-008) write the definitions.

Residual risks and open points:
- **Serialised writers.** Requests for one gap-free counter wait for each other until each transaction commits. The cost is accepted with the owner's decision. The business transaction that takes a number must stay short; measure under load in S1.
- **Reference data.** Dial codes outside the GCC need an ITU source, and the GCC weekends need confirmation (Q-CAT-12); both are in O-25. Taking a newer ISO version means running the generator again.
