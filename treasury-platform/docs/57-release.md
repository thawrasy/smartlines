## 3. ملفات الحزمة

تُنزَّل من صفحة الإصدار `bankfas-v1.0.6` في GitHub. الحزمة خاصة مثل المستودع، فيلزم حساب له صلاحية عليه.

| الملف | ما هو |
|---|---|
| `bankfas-api-1.0.6.tar.gz` | صورة خادم التطبيق: الواجهة، والخدمات، وطابعة PDF |
| `bankfas-worker-1.0.6.tar.gz` | صورة المهام الخلفية: البريد، والإشعارات، والمهام المجدولة |
| `bankfas-source-1.0.6.tar.gz` | مصدر الإصدار: أدوات النشر (`tools/deploy` و`tools/host`)، وسكربتات قاعدة البيانات (`db`)، والوثائق كلها، ومنها دليل النشر `docs/54` |
| `INSTALL-AR.md` و`INSTALL-AR.docx` | هذا الدليل |
| `VERSION.txt` | رقم الإصدار، ورقم الحفظة (commit) التي بُني منها، ومعرّفا الصورتين |
| `SHA256SUMS` | بصمة SHA-256 لكل ملف |

الصورتان هما نفسهما اللتان اجتاز عليهما اختبار التشغيل التجريبي في GitHub في البناء نفسه. وصُنعت الحزمة من الصورتين نفسيهما مباشرة، فلم يُعَد بناؤهما بعد الاختبار.

## 4. التثبيت على الخادم

الخطوات هي خطوات دليل النشر `docs/54` كما هي، بفرق واحد: **الخطوة R-01 (بناء الصورتين) تصير تحميلهما من الحزمة.**

**1. التحقق من الحزمة**، على كل خادم تُنقل إليه:

```bash
cd ~/bankfas-1.0.6
sha256sum -c SHA256SUMS          # كل سطر يجب أن ينتهي بـ OK
tar -xzf bankfas-source-1.0.6.tar.gz
cd treasury-platform              # كل أوامر docs/54 تُنفّذ من هنا
```

**2. خادم قاعدة البيانات:** الأجزاء B ثم D من `docs/54`، بأدوات `tools/deploy` من المصدر المستخرج.

**3. خادم التطبيق:** الجزء H من `docs/54`، ثم بدل R-01:

```bash
sudo docker load -i ~/bankfas-1.0.6/bankfas-api-1.0.6.tar.gz
sudo docker load -i ~/bankfas-1.0.6/bankfas-worker-1.0.6.tar.gz
sudo docker image ls | grep bankfas    # bankfas-api:1.0.6 و bankfas-worker:1.0.6
```

**4. الخطوة R-02:** في `/opt/bankfas/compose.yml` يُكتب اسما الصورتين `bankfas-api:1.0.6` و`bankfas-worker:1.0.6`، بلا اسم سجل. ثم تُكمل R-02a إلى R-08 كما في الدليل.

## 5. قبل البدء

- **ما يلزم من الخادم:** `docs/55` يجمع ما يلزم من الخادم ومن مزود الخدمة: النطاق، والبريد، والشهادة، والمنافذ. وملف القيم `tools/host/site.conf.example` يجمعها في مكان واحد.
- **قبل بيانات حقيقية:** الإصدار للتجربة. تبدأ التجربة بمشترك تجريبي وبيانات توضيحية.
- **التحقق من البيئة:** يُشغَّل `tools/host/check_ready.sh` قبل أول تشغيل، ويجب أن يخرج بصفر.

## 6. كيف يُبنى إصدار جديد

- **الرقم:** يُكتب رقم الإصدار في الملف `RELEASE` في جذر `treasury-platform`، ويُحدَّث هذا الدليل له: جدول الإصدارات، وأسماء الملفات في أوامره. والسكربت يرفض البناء إن لم يذكر الدليل ملفات الإصدار.
- **الإطلاق:** تُرفع حفظة في رسالتها `[release]`.
- **ما يحدث بعدها:** مهمة الصور في GitHub تبني الصورتين، وتشغّل عليهما اختبار التشغيل التجريبي كاملًا. فإن نجح، صنعت الحزمة بـ `tools/release/make_release.sh` ونشرتها إصدارًا تجريبيًا باسم `bankfas-v<الرقم>`. وإن فشل الاختبار لا يُنشر شيء.
- **البناء محليًا:** السكربت نفسه يعمل على أي جهاز فيه Docker وgit، بالصورتين اللتين يُعطاهما.
