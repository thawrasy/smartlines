## 3. ملفات الحزمة

تُنزَّل من صفحة الإصدار `bankfas-v1.0.8` في GitHub. الحزمة خاصة مثل المستودع، فيلزم حساب له صلاحية عليه.

| الملف | ما هو |
|---|---|
| `bankfas-1.0.8-server.tar` | **الملف الواحد الذي يُرفع إلى الخادم**: فيه كل ما يلي عدا الوثائق، في مجلد `bankfas-1.0.8`. وبجانبه `bankfas-1.0.8-server.tar.sha256` |
| `bankfas-images-1.0.8.tar.gz` | الصورتان معًا: `bankfas-api:1.0.8` (الواجهة والخدمات وطابعة PDF) و`bankfas-worker:1.0.8` (البريد والإشعارات والمهام المجدولة). الطبقات المشتركة بينهما مرة واحدة |
| `bankfas-kit-1.0.8.tar.gz` | أدوات التثبيت: `tools/deploy` و`tools/host` وسكربتات قاعدة البيانات `db`، بلا وثائق |
| `bankfas-docs-1.0.8.tar.gz` | الوثائق كلها، ملف منفصل يُحفظ على جهاز أو في مساحة تخزين للشركة، ولا يلزم الخادم |
| `INSTALL-AR.md` و`INSTALL-AR.docx` | دليل التجربة الخاصة بعنوان IP (`docs/62`) |
| `RELEASE-NOTES-AR.md` | هذه الملاحظات |
| `VERSION.txt` | رقم الإصدار، ورقم الحفظة (commit) التي بُني منها، ومعرّفا الصورتين |
| `SHA256SUMS` | بصمة SHA-256 لكل ملف |

الصورتان هما نفسهما اللتان اجتاز عليهما اختبار التشغيل التجريبي في GitHub في البناء نفسه. وصُنعت الحزمة من الصورتين نفسيهما مباشرة، فلم يُعَد بناؤهما بعد الاختبار.

## 4. التثبيت على الخادم

- **التجربة الخاصة بعنوان IP، دون نطاق:** `docs/62` خطوة بخطوة، وهو `INSTALL-AR` في الحزمة.
- **منصة بنطاق:** خطوات دليل النشر `docs/54`، بفرق واحد: الخطوة R-01 (بناء الصورتين) تصير تحميلهما من الحزمة.

**1. التحقق من الحزمة**، على كل خادم تُنقل إليه:

```bash
sha256sum -c bankfas-1.0.8-server.tar.sha256
tar -xf bankfas-1.0.8-server.tar
cd bankfas-1.0.8
sha256sum -c --ignore-missing SHA256SUMS   # كل سطر يجب أن ينتهي بـ OK؛ ملف الوثائق ليس هنا
tar -xzf bankfas-kit-1.0.8.tar.gz
cd treasury-platform                         # كل أوامر الأدلة تُنفّذ من هنا
```

**2. خادم قاعدة البيانات:** الأجزاء B ثم D من `docs/54`، بأدوات `tools/deploy` من الحزمة المستخرجة.

**3. خادم التطبيق:** الجزء H من `docs/54`، ثم بدل R-01:

```bash
sudo docker load -i ~/bankfas-1.0.8/bankfas-images-1.0.8.tar.gz
sudo docker image ls | grep bankfas    # bankfas-api:1.0.8 و bankfas-worker:1.0.8
```

**4. الخطوة R-02:** في `/opt/bankfas/site.conf` يُكتب اسما الصورتين `bankfas-api:1.0.8` و`bankfas-worker:1.0.8`، بلا اسم سجل، فيكتبهما `provision_app_host.sh` في `compose.yml`. ثم تُكمل R-02a إلى R-08 كما في الدليل.

## 5. قبل البدء

- **ما يلزم من الخادم:** للتجربة بعنوان IP يكفي خادم Ubuntu 24.04 وعنوانه (`docs/62`). ولمنصة بنطاق: `docs/55` يجمع ما يلزم من الخادم ومن مزود الخدمة: النطاق، والبريد، والشهادة، والمنافذ. وملف القيم `tools/host/site.conf.example` يجمعها في مكان واحد.
- **قبل بيانات حقيقية:** الإصدار للتجربة. تبدأ التجربة بمشترك تجريبي وبيانات توضيحية.
- **التحقق من البيئة:** يُشغَّل `tools/host/check_ready.sh` قبل أول تشغيل، ويجب أن يخرج بصفر.

## 6. كيف يُبنى إصدار جديد

- **الرقم:** يُكتب رقم الإصدار في الملف `RELEASE` في جذر `treasury-platform`، ويُحدَّث هذا الدليل له: جدول الإصدارات، وأسماء الملفات في أوامره. والسكربت يرفض البناء إن لم يذكر الدليل ملفات الإصدار.
- **الإطلاق:** تُرفع حفظة في رسالتها `[release]`.
- **ما يحدث بعدها:** مهمة الصور في GitHub تبني الصورتين، وتشغّل عليهما اختبار التشغيل التجريبي كاملًا. فإن نجح، صنعت الحزمة بـ `tools/release/make_release.sh` ونشرتها إصدارًا تجريبيًا باسم `bankfas-v<الرقم>`. وإن فشل الاختبار لا يُنشر شيء.
- **البناء محليًا:** السكربت نفسه يعمل على أي جهاز فيه Docker وgit، بالصورتين اللتين يُعطاهما.
